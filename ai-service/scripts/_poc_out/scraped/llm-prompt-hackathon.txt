LLM 프롬프트 해커톤: MVP 서비스 구현

팀 기반 해커톤 방식으로 LLM 활용 전략과 프롬프트 엔지니어링을 학습하고,


문제정의 → 설계 → 구현 → 평가/개선 → 발표까지 3일 동안 MVP를 완성하는 프로젝트 중심 과정입니다.


강의(마이크로러닝)와 실습(스프린트)을 교차 운영하여, “만드는 과정” 자체가 학습이 되도록 설계했습니다.



학습 목표
LLM 서비스 기획 관점에서 문제정의·사용자 스토리·성공지표를 구조화할 수 있다.
업무형 프롬프트 패턴(지시/제약/출력스키마/근거/실패처리)을 적용해 결과 품질을 안정화할 수 있다.
테스트셋·루브릭 기반으로 결과를 평가하고, 프롬프트/지식베이스/UX를 반복 개선할 수 있다.
MVP를 구현하고(노코드/로우코드), 운영·보안·가드레일 관점의 적용 방안을 제시할 수 있다.
학습 대상
LLM을 활용한 업무/서비스 아이디어를 실제 MVP로 구현해보고 싶은 공공·민간 실무자
프롬프트를 “잘 쓰는 것”을 넘어 “평가하고 개선하는 방법”을 체득하고 싶은 팀
교육과 프로젝트를 함께 수행해 단기간에 성과물(데모/템플릿/가이드)을 확보하고 싶은 조직
교육 성과(산출물)
[Gate 1] 문제정의 1p + 사용자 스토리(5개 이상) + 성공지표(KPI/성공기준)
[Gate 2] 프롬프트 v1 + 테스트셋(20~30문항) + 채점 루브릭(평가기준표)
[Gate 3] MVP 데모(필수 기능 3개) + 평가/개선 로그(최소 2~3회 반복)
[Gate 4] Executive Summary 1p + 운영/보안/가드레일 가이드 + 최종 발표자료
교육 시간
3일 - 24H (1일 8H)
Day 1 Day 2 Day 3
시간	파트	내용 및 학습목표
09:00 ~ 10:00	오리엔테이션 & 팀빌딩	
목표: 과정 운영 규칙, 평가 기준, 산출물을 공유하고 팀을 구성한다.
해커톤 운영 방식: 마이크로러닝(교육) ↔ 스프린트(적용) ↔ 리뷰(피드백) 반복
팀 구성/역할 배정(권장): PO/PM, Prompt Lead, Builder, Data/RAG, QA/Red Team
산출물: 팀/역할 확정 + 아이디어 후보 2~3개

10:00 ~ 11:00	마이크로러닝 1: LLM 서비스 기획의 정석	
목표: “무엇을 만들지”를 문제정의와 사용자 관점으로 고정한다.
Problem Statement / Persona / JTBD / 가치 제안(가치·비용·리스크)
성공기준: 정량 KPI(예: 처리시간, 정확도, 만족도) + 품질 기준(근거/안전)

11:00 ~ 12:00	스프린트 1: 문제정의 1p & 사용자 스토리	
목표: 팀별 프로젝트의 범위와 성공기준을 확정한다.
사용자 스토리 5개 이상(입력→처리→출력), 핵심 기능 3개(필수) 정의
Gate 1 제출: 문제정의 1p + 사용자 스토리 + 성공기준

12:00 ~ 13:00	점심 시간	휴식
13:00 ~ 14:00	마이크로러닝 2: 프롬프트 패턴(업무형) & 출력 스키마	
목표: 프롬프트를 “재현 가능한 절차”로 만든다.
Role/Goal/Context/Constraints/Output Schema(표준 템플릿)
근거 요구(출처/근거/계산), 실패 처리(ask-back), 금지/제약(보안·개인정보)

14:00 ~ 15:00	마이크로러닝 3: 평가(Eval) 설계(테스트셋·루브릭·로그)	
목표: “좋아 보인다”가 아니라 “개선됐다”를 만들 수 있도록 평가를 고정한다.
테스트 케이스 유형: 정답형/근거형/금지형/엣지케이스
루브릭(채점표): 정확성/근거/형식준수/안전/유용성 중 3~5개 선택

15:00 ~ 18:00	스프린트 2: 프롬프트 v1 + 테스트셋 구축	
목표: MVP 구현 전, 품질을 통제할 수 있는 “프롬프트+평가”를 먼저 완성한다.
프롬프트 v1 작성(출력 JSON/표 스키마 권장) + 테스트셋 20~30문항
초기 평가 수행(점수 기록) 및 개선 포인트 3개 도출
Gate 2 제출: 프롬프트 v1 + 테스트셋 + 루브릭 + 초기 점수
※ Day 1은 “무엇을/어떻게/어떤 기준으로” 만들지 확정하는 날입니다(프롬프트+평가가 핵심).
