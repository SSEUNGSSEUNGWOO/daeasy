## 사람 손이 필요한 수동 테스트 (예진님용 절차)

자동 검증은 `tests/config.검증.yaml`(세션 경로를 없는 이름으로 바꾼 설정)로 돌려
6단계가 두 채널 모두 **skipped** 되는 것까지 확인한다. 실제 draft 업로드는 실계정
세션이 필요하므로 아래는 사람이 돌린다.

### 5-② 로그인 후 skipped 채널 재시도 (C18)
1. pr-publish에서 `uv run prpub site-login` (네이버는 이미 `.naver-profile/` 있음)
2. 기본 config로 재실행 (ai-service/ 에서): `uv run python promo/run.py --slug <slug>`
3. 기대: 연구·작성·채점은 전부 스킵(품질 게이트), draft skipped 채널만 재시도.
   네이버는 브라우저가 뜨고 본문 입력 후 발행 직전 정지(~13분) → `ok` 또는
   타임아웃 시 미리보기 PNG 존재로 `draft_ready`.

### 5-③ stale draft 수렴 (C23)
1. site draft가 `ok`로 올라간 상태에서 `out/<slug>/post.md`를 한 글자 수정
2. 재실행 → 수동 편집 감지로 judge부터 재통과 → site 채널에서
   `already_exists_stale` 경고("기존 draft는 이전 본문…") 확인
3. 삭제 없이 한 번 더 재실행 → 같은 경고에 멱등 수렴(다른 부작용 없음) 확인
4. 어드민(https://daeasy.co.kr/admin/cases)에서 기존 draft 삭제 → 재실행 →
   `ok` + 새 content_hash 기록 확인

### 5-④ 발행 안전핀 (C15)
- `python -O` 로 실행해도 `ensure_no_publish_flags`가 살아 있는지:
  `uv run python -O promo/run.py --slug <slug>` → draft 단계 정상 (assert 미사용이므로 -O 무관)
- 코드에서 `--publish`/`--live`가 인자에 섞이는 경로가 없음을 draft.py에서 확인

### 7 사이클 재진입·크래시 복구 (C16·C17·C24)
1. `config.yaml`의 `judge.pass_score`를 일시적으로 15로 올려 5.5를 강제 불통과시키면
   로그에서 `상한 판정 → begin_next_cycle(단일 save_state) → rewrite` 순서 확인 가능
2. rewrite 도중 Ctrl+C → `state/<slug>.json`에서 judge=pending·cycle=2 영속 확인 →
   재실행 시 judge 루프부터 재가동(자체 수습) 확인
3. 사이클 2 도중 Ctrl+C 후 재실행 → 로그의 "사이클 2/2 진입"으로 `cycle==2` 복원 확인

### 6 완주 후 재실행 멱등성
- 완주한 건을 그대로 재실행 → 품질 게이트로 4·5·5.5 스킵, done 채널 스킵,
  산출물 무파괴("완료 — 스킵" 로그만) 확인
