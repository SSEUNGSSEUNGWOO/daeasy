# 인사이트 Writer 원문 본문 확보 — 설계

작성: 2026-09-08

## 배경

- 2026-09-08 발행이 3회 연속 탈락한 원인을 추적하면서 심사 피드백에 매번 "근거보다 단정적", "수치의 조사 대상·정의 불명" 이 반복됐다. 원자료를 열어 보니 Writer 에 전달되는 `content` 가 **RSS 요약**이었다 — 77건 실측 중앙값 74~300자, `kr_ai_policy`(AI타임스)는 피드가 정확히 300자에서 자른다. 77건 합쳐 15,052자.
- 그런데 Writer 프롬프트는 "구체적 수치, 주요 이해관계자, 기술적 세부사항, 배경 맥락을 포함해 4~6문장" 을 요구한다. 300자 요약에서 그걸 쓰라는 것이라 모델이 빈 곳을 사전지식·과장으로 메운다. 82% 통계의 모집단 바꿔치기가 그 예.
- 외부 리뷰의 "주제를 고른 뒤 선정된 출처의 본문을 충분히 전달하라" 는 제안은 방향은 맞지만 **늘릴 원문이 로컬에 없다** — 프롬프트 재구성이 아니라 기사 본문을 실제로 가져오는 네트워크 단계가 필요하다.

## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 시점 | **작성 시점**, 선정된 출처만 (A안) | 크롤 시점 전량 fetch(B안)는 매일 77건 네트워크 + git 추적 raw 디렉토리가 하루 200KB 씩 불어남. 클러스터링은 200자만 써서 이득 없음. 프롬프트만 손보기(C안)는 데이터상 효과 0 |
| 선정 기준 | 이미 있는 `cluster_items()` 의 `importance >= 3` 클러스터 항목 | 새 선정 로직을 두지 않는다. 15~25건 |
| 대상 소스 | `ai_news`, `ai_blogs`, `kr_ai_policy` | RSS 요약 소스. GitHub·HF·arXiv 는 지금 `content` 가 곧 원문(description / abstract) |
| 추출 | bs4 로 `script/style/nav/header/footer/aside/form/iframe` 제거 → `<article>` 있으면 그 안, 없으면 `<body>` 에서 **40자 이상 `<p>`** 만 모아 3,000자 상한 | readability·trafilatura 추가 안 함. 설치된 의존성으로 충분 |
| 폴백 | 추출 결과가 기존 요약의 2배 미만이면 실패로 보고 요약 유지. 네트워크 실패도 요약 유지 | 페이월·JS 렌더 껍데기를 걸러낸다. 지금보다 나빠지는 경로가 없어야 한다 |
| 프롬프트 반영 | "전체 수집 항목" 에서 확보된 항목만 `본문(원문 발췌):` 로 표기. 선정 항목은 `items[:50]` 컷과 무관하게 포함(번호 체계 유지). `prompts.py` 에 "원문 발췌가 있는 항목은 발췌를 근거로 쓴다" 한 줄 | 기존 "수치·고유명사는 출처에서 확인 가능한 것만" 규칙이 비로소 지킬 수 있는 규칙이 된다 |
| 캐시 | 모듈 레벨 `dict[url → text \| None]` | 평가 탈락 후 재작성 3회 동안 재요청 없음. 실패도 캐시. raw JSON 에는 저장 안 함 |
| 속도 | **순차 + 1초 간격**, 재시도 없음, 브라우저형 UA | 처음엔 8 스레드 병렬로 잡았으나 실측에서 단독 테스트 47건 + dry run 32건을 10분 안에 쏘자 AI타임스가 IP 를 403 으로 막았다. 그 소스가 원자료의 절반이라 속도보다 차단 안 당하는 게 우선. 하루 20~30건 ≈ 30초 |
| 위치 | `shared/utils.py` 에 `extract_article_text`(순수) + `fetch_article_text`(= `safe_get` + 추출). `writer.py` 의 `write_report()` 가 호출 | `fetch_og_image` 와 같은 층. 파일 2개 + 프롬프트 1줄 |

## 검증

1. `extract_article_text` 자체 체크 — 합성 HTML(article + nav 잡음)에서 p 텍스트만 나오는지 (`writer.py __main__`)
2. 실제 URL 3개(AI타임스·TechCrunch·OpenAI 블로그)로 추출 길이·첫 줄 확인 — 사이트별 구조가 제일 큰 리스크
3. `writer.run()` + `evaluator.run()` 만 호출 — DB 저장·발행 없이 심사 피드백에서 "근거 부족" 지적이 줄었는지 확인. 같은 날 원자료라 비교가 깨끗하다

## 하지 않는 것

- readability/trafilatura 등 새 의존성
- 크롤러·raw 저장 형식 변경
- GitHub README fetch
- 선정 로직 신설

## 미정 / 다음

- 프롬프트가 15k → 50~70k자로 커진다. `run_claude(timeout=300)` 이 부족하면 올린다.
- 추출이 약한 사이트가 드러나면 사이트별 셀렉터를 두지 말고 폴백(요약 유지)으로 둔다. 셀렉터 표는 유지비가 이득보다 크다.
