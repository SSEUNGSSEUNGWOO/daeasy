# 인사이트 → 네이버 블로그 티저 초안 — 설계

작성: 2026-09-09

## 배경

- 승우님: "인사이트 출간할 때 `blog.naver.com/daeasy_official` 에 같이 올리기 가능하려나".
- 네이버 블로그는 글쓰기 API 가 없다. 이 저장소의 홍보발행 파이프라인(`promo/`)이 이미 pr-publish 의
  `prpub naver <slug>` (로그인된 브라우저 세션으로 에디터를 채우고 **발행 직전에 정지**)를 쓰고 있어, 인사이트도
  같은 부품을 빌린다.

## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 내용 | **티저** — 헤드라인 + 항목별 소제목·첫 문장 + 전문 링크 | 전문을 두 곳에 두면 네이버는 canonical 을 안 봐서 사이트와 블로그가 서로 경쟁한다. 조회·좋아요·문의는 사이트에 있다 |
| 발행 | **사람이 클릭** — `prpub naver` 무발행 모드(에디터에 채운 뒤 정지) | 자동 생성 글이 검수 없이 나가는 걸 막는 마지막 문. `--publish` 는 코드에서 붙이지 않는다 |
| 위치 | `insights/naver_teaser.py`, `run.py` 의 뉴스레터 다음 단계 | 뉴스레터와 같은 "부가 기능" — 실패해도 발행은 이미 끝난 상태 |
| pr-publish 위치 | `PRPUB_ROOT` 환경변수 → 없으면 `promo/config.yaml` 의 `prpub.root` | promo 와 같은 규약. 폴더가 없거나 `.naver-profile` 세션이 없으면 한 줄 남기고 건너뛴다 |
| naver.md | frontmatter `제목:`(≤60자) / `카테고리:` / `태그:`(12~16개) / `대표사진: images/cover.jpg` + 본문 `[대표사진]` + 평문 문단 + URL 한 줄 | promo writer 프롬프트가 명시한 규격만 쓴다. 본문 세부 규격(`홍보발행.md` 5절)은 pr-publish 안에 있어 이 PC 에서 못 봤다 — 평문·URL 이라는 안전한 부분집합 |
| 카테고리 | 환경변수 `NAVER_INSIGHT_CATEGORY`, 기본 `AI 인사이트` | 블로그에 그 카테고리가 있어야 한다. 없으면 만들거나 env 로 바꾼다 |
| 태그 | 인사이트 태그(3~5) + 고정 풀(`AI, 인공지능, 데이터, 공공기관, …`)로 16개 | 규격 12~16 |
| 대표사진 | 커버(Unsplash) 를 `out/<slug>/images/cover.jpg` 로 내려받음. 실패하면 사진 없이 | 본문 og:image 는 출처 사진이라 블로그 대표사진으로 쓰지 않는다 |

## 검증

- 자체 체크(`naver_teaser.py __main__`): 항목·첫 문장 추출, 제목 60자 컷, 태그 개수, 사진 유무별 자리표시
- 오늘 실제 인사이트로 naver.md 렌더 확인
- **`prpub naver` 실행은 pr-publish 가 있는 PC 에서 첫 발행 때 검증** — 이 PC 엔 그 프로젝트가 없다

## 하지 않는 것

전문 게시, 자동 발행(`--publish`), 네이버 API 흉내, 블로그 카테고리 자동 생성.
