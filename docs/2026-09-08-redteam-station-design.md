# AI 체험관 스테이션 03 레드팀 게임 — 설계

작성: 2026-09-08

## 배경

- `/quiz` 허브에 STATION 03 "레드팀 게임" 이 *"가드레일이 걸린 AI 챗봇을 직접 뚫어보며 배우는 보안 감각"* 으로 예고만 돼 있었다 (`href: null`, "오픈 예정").
- 승우님 조건: **API 없이**. 01·02 와 같이 런타임 LLM 호출 없이, 미리 써둔 응답을 재생한다. Vercel 에 AI 키 불필요, 비용 0.

## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 형식 | **공격자 — 뚫어보기.** 라운드마다 규칙이 보이는 공공 챗봇 + 공격 프롬프트 4개 중 선택 → 봇 답변 타자기 재생 → `뚫림/막힘` 판정 + 이유 → 다음 | 허브 예고 문구 그대로. 방어자 형식은 교훈은 직접적이지만 "뚫는" 재미가 약함. 둘 다 하면 콘텐츠·화면이 2배 |
| 라운드 | 5개, 취약점 한 종류씩: ① 사회공학(신분 사칭) ② 간접 프롬프트 인젝션(문서 속 지시) ③ 도구 오남용(메일 수신자 바꿔치기) ④ 시스템 프롬프트 유출(형식 우회) ⑤ 확신 유도(환각) | 공공 실무자가 실제로 만나는 순서. ②는 2026-09 오픈AI '위키 사건', ⑤는 제미나이 등산객 구조 사례와 연결 |
| 선택지 | 4개 중 1~2개만 뚫림. 봇 규칙이 화면에 보여 추리 게임이 된다 | 전부 뚫리면 게임이 아니고, 전부 막히면 배울 게 없다 |
| 점수 | 첫 선택만 집계. 판정 후 "다른 말들은?" 펼침으로 나머지 3개 판정 한 줄씩 | 한 번 고르고 끝나면 3/4 의 교훈을 버린다. 펼침은 점수와 무관 |
| 결과 | `N/5 뚫음` + 다섯 원칙(뚫어본 것 표시) + 과정 추천 카드 2개 | 01 과 같은 마무리. 추천 slug 는 콘텐츠에 고정, 제목·레벨은 DB 에서 (없으면 카드 생략) |
| 콘텐츠 | `quiz/redteam/content.ts` TS 상수 | 01·02 의 JSON 은 Gemini 생성물이라 fetch 하지만, 이건 손으로 쓰는 시나리오. 타입 있는 모듈이면 fetch·로딩·null 처리가 없다 |
| 타자기 | 파일 안 `BotReply` 컴포넌트 (key 로 재마운트, interval 안에서만 setState) | 01 의 로직을 30줄로 축약. 01·02 는 건드리지 않는다 |
| 저장 | 없음 — 점수·랭킹·타이머 없음 | YAGNI |
| 일러스트 | 허브 카드 일러스트는 `/illust/quiz-redteam.webp` 가 생기면 `STATION_ILLUST` 에 한 줄 | 승우님 ComfyUI 몫. 없어도 카드는 정상 |

## 화면 흐름

인트로(규칙 한 문단, 시작 버튼) → 라운드 n/5: 챗봇 카드(이름·용도·규칙) + 선택지 4 → 선택 시 봇 답변 타자기 → 완료되면 판정 배지 + 이유 2문장 + "다른 말들은?" → 다음 라운드 / 결과 보기 → 결과 화면.

## 검증

- `npm run lint && npm run build`
- dev 서버에서 5라운드 클릭 스루 (Playwright) — 판정·점수·결과·추천 카드, 모바일 폭

## 하지 않는 것

자유 입력, 점수 저장, 타이머, 애니메이션 라이브러리, 런타임 LLM.
