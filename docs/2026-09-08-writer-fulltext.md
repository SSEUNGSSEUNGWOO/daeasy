# 인사이트 Writer 원문 본문 확보 — 구현 기록

작성: 2026-09-08 · 설계: [2026-09-08-writer-fulltext-design.md](2026-09-08-writer-fulltext-design.md)

## 구현

| 파일 | 내용 |
|---|---|
| `ai-service/shared/utils.py` | `extract_article_text(html, max_chars)` — 직계 `<p>` 텍스트가 가장 많은 컨테이너를 본문으로 보고 40자 이상 `<p>` 만 모음. `fetch_article_text(url, max_chars)` — `safe_get`(재시도 없음, 브라우저형 UA) + 추출. `safe_get` 에 `headers` 옵션 추가 |
| `ai-service/insights/writer/writer.py` | `FULLTEXT_SOURCES`, `FULLTEXT_MAX_CHARS=3000`, 모듈 캐시 `_FULLTEXT_CACHE`, `fetch_fulltexts(items, indices)` (순차, 1초 간격, 요약 2배 미만이면 폴백). `write_report()` 가 주요 클러스터 항목을 `selected` 로 모아 본문을 가져오고, "전체 수집 항목" 에서 그 항목은 `본문(원문 발췌):` 로 표기. 선정 항목은 `items[:50]` 컷과 무관하게 포함 |
| `ai-service/insights/writer/prompts.py` | 사실 검증 규칙에 "원문 발췌가 있는 항목은 발췌를 근거로, 통계는 조사 주체·대상을 그대로" 추가. **출처 `1~3개` 상한 문구 제거** (아래) |

## 실측

### 추출기 — 오늘 원자료 47건(대상 소스 전체)

| 소스 | 확보 | 비고 |
|---|---|---|
| ai_news (TechCrunch 등) | 7/7 | |
| kr_ai_policy (AI타임스) | 34/37 | |
| ai_blogs (openai.com) | 0/3 | Cloudflare 403 — UA 무관. 포기, 요약 유지 |
| **합계** | **41/47 (87%)** | 확보 본문 중앙값 **1,533자** (RSS 요약 300자의 5배) |

첫 버전은 "첫 `<article>`" 을 본문으로 잡아 1/4 였다. AI타임스는 관련기사 카드가 `<article>` 로 먼저 나오고, TechCrunch 는 `<article>` 없이 배너 `<p>` 가 앞에 있었다. "직계 `<p>` 가 가장 많은 컨테이너" 규칙 하나로 둘 다 해결 — 사이트별 셀렉터 없음. 자체 체크(`writer.py __main__`)에 두 실패 사례를 합성 HTML 로 박아뒀다.

### 차단 — AI타임스 403

추출 테스트 47건 직후 dry run 이 32건을 8스레드로 더 쏘자 AI타임스가 IP 를 403 으로 막았다 (146~548바이트 차단 페이지, UA 바꿔도 동일). dry run 은 `원문 본문 6/32건 확보` 로 끝나 원문 효과를 거의 측정하지 못했다. 그 소스가 원자료의 절반이라 **속도보다 차단 안 당하는 게 우선** — 병렬을 버리고 순차 1초 간격, 403 에 재시도 안 함으로 바꿨다. 하루 1회 20~30건이면 30초.

### dry run (writer → 이미지 → 교정 → 평가, 발행 없음)

- 4.34 통과 (factual 4.1 / relevance 4.8 / insight 4.6 / source_linkage 3.7 / seo 4.5 / voice 4.4 / image 3.8). 원문이 6건만 들어간 상태라 **원문 효과의 근거로 쓰지 않는다**.
- 부수 발견: 링크 누락 체크가 6건을 잡았고 심사위원도 같은 지적(source_linkage 3.7). 원인은 프롬프트 모순 — `출처: 1~3개` 상한과 `언급한 도구는 반드시 URL` 규칙이 충돌해 도구 6개를 쓰면 위반이 보장됐다. 상한 문구를 "언급한 출처·도구마다 하나씩" 으로 바꿨다.

## 검증 상태

- 자체 체크 통과: 링크 누락 감지, 추출기(배너·카드·캡션 배제)
- 추출기 실전 87% 확보 (위)
- **원문이 심사 피드백("근거 부족·단정")을 줄이는지는 아직 미측정** — 차단 때문에. 다음 실발행 로그의 `[writer] 원문 본문 N/M건 확보` 가 80% 이상인지, 피드백에서 "출처 범위를 넘는 단정" 지적이 줄었는지로 판단한다.

## 운영 주의

- 테스트 목적으로 대량 fetch 하지 말 것 — 하루 발행 1회분(20~30건)이 상한. 차단되면 그날은 요약으로 폴백돼 글은 나가지만 근거가 얇아진다.
- 차단 여부는 `[writer] 원문 본문 N/M건 확보` 로 드러난다. 갑자기 낮으면 `curl -I https://www.aitimes.com/...` 로 403 인지 본다.
